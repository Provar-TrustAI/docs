<Update label="v2026.09.09.2 — September 2026">
  **Test data plans and run reports are on by default.** The plan editor and the per-run report that shipped switched off in v2026.09.09.1 are now part of every build, with an explicit opt-out for operators who need one. Whole-plan JSON editing stays available in the Trust Agent fly-in and for any plan the structured form cannot represent. See [Scenarios](/concepts/scenarios).

  **A Salesforce test-data run survives a worker restart.** Reserving an environment, capturing what the run left behind, and releasing it are now recorded durably and serialized per environment, so a run that acquired data on one worker can still capture and release it on another. Seeded records are removed by exact id in reverse order — including when the plan authored no explicit reset step.

  **A drafted plan asserts the change you asked for.** AI drafting now separates evidence it gathers along the way from the end state it is asserting, so a requested change lands in the plan as an expectation instead of disappearing from it, and the summary matches the plan it generated. Salesforce schema discovery also resolves the active flow and the objects it uses, narrows fields to what the connected user can actually see, and reports the actions it could not resolve rather than claiming broader access.

  **Results read more honestly.** A collapsed row now aggregates its child results instead of reporting only its own, opaque user identifiers no longer reach the screen, and an infrastructure failure is described as one.
</Update>

<Update label="v2026.09.09.1 — September 2026">
  **A scenario's test data is now one plan.** What a test creates, what it reads back, what it compares, and what it removes are authored together and render as five step cards — **Create what this test needs**, **Run the conversation**, **Read back what the agent created**, **Check what should happen** and **Clean up everything this test created**. Start from **Set up with AI** or **Add manually** on an empty plan, and **Edit plan** thereafter; all three open the same docked drawer, which offers AI drafting, a form, and an explicit JSON mode. An AI proposal is always reviewable before it replaces what you had saved.

  **The plan says where the data lives and what will be removed.** Environment configuration sits with the agent connection, so you can see the store a test runs against, how its records are attributed to that test, and whether the test **Runs alongside other tests (recommended)** or **Runs alone**. The **Check what should happen** step holds the **Expected end state** — the records a finished run should find, which is a separate contract from the scenario's own Expected Output. Cleanup cannot be turned off and says exactly what it does: *Removes only the records each test created.*

  **A run report records what actually happened.** Every run keeps its own account of setup, read-back, structural results and cleanup, and links back to the scenario's plan — so a failed comparison can be traced to the data it ran against rather than guessed at.

  **These screens shipped switched off in this release's published build.** The plan editor and the run report landed complete but gated, and the build published for this version leaves them off; they are on by default from v2026.09.09.2. Two frontend build failures were also cleared here, with no change to product behaviour.
</Update>

<Update label="v2026.09.07.1 — September 2026">
  **A quick evaluation is something you can watch.** Grading one conversation from its own fly-in used to close in silence and show you a verdict only if you thought to reopen the panel. It now opens with a **Quick evaluation started** toast, shows a Queued and then Running card on the session, counts the checks as they land — *Scoring check 2 of 3…* — and finishes with a **Quick evaluation finished** toast carrying a **View** action. The progress lives on the server, so it survives a reload and a colleague in another tab sees the same thing. See [Evaluations](/concepts/evaluations).

  **Quick evaluations appear on the Evaluations page.** They mint no run record by design, so the page never listed them. They are now ordinary rows carrying a muted **Quick** pill, and opening one takes you to the conversation it graded rather than a run detail page that does not exist. Those rows have no Cancel and no Delete, and the sidebar's Evaluations count still counts full runs only.

  **Re-running a quick evaluation replaces the grade instead of discarding it.** Evaluating an already-graded conversation used to run every judge, charge for every one, and then keep the previous verdict. The new grade now replaces the old one in the same transaction, so the conversation is never without a grade and never carries two, and a redelivered request neither re-grades nor re-charges.

  **Judges stay inside the transcript.** On real multi-turn Agentforce runs both language-model judges continued the conversation past its last turn and quoted tool calls that never ran. The transcript is now declared complete, a tool call is anchored to the turn it happened on and carries what it returned, and the structural grader compares action and route names canonically — so a catalog label and its developer-name spelling are recognised as the same thing instead of failing the check.

  **Two interaction fixes.** A multi-select filter option now toggles once when you click anywhere on its row; it had been toggling twice and netting zero, so only a precise hit on the checkbox worked. And the Trust Agent's send control stays inert until the conversation history has loaded, instead of accepting an Enter the submit path would silently hold back.
</Update>

<Update label="v2026.09.02.1 — September 2026">
  **Two evaluation runs can be compared, and the answer is allowed to be "we can't tell."** Change your agent, re-run the same scenarios, and TrustAI will say whether it helped — **Better**, **Worse**, **Too close to call**, or a refusal reading *"We can't compare these fairly."* Comparability is judged first and a withheld verdict computes nothing: if an evaluator's rubric moved between the two runs, the two scores came from different rules and the comparison is refused rather than quietly rendered, and scenarios present in only one run are reported instead of counted as zeros. This is an API surface today — nothing in the app renders it — and its shape is provisional, since the team has since decided to rebuild it at a finer grain. See the [API Reference](/api-reference).

  **Adding another Salesforce agent from Settings reuses the authorization you already have.** The wizard now offers the organizations you can already reach, from this project and from others, instead of always starting a fresh sign-in — and reusing one goes straight to picking the agent, with no second application provisioned in your org. It also pins the exact organization you chose, so an older connection to the same host cannot be picked by accident. Separately, a captured Agentforce profile now comes from the version of the agent that is actually live: discovery reads the active version from the org and follows Salesforce's own links from planner to topic to action, and refuses rather than guessing when the active version cannot be identified. See [Manage Salesforce connections](/how-to/manage-salesforce-connections).
</Update>

<Update label="v2026.08.31.1 — August 2026">
  **TrustAI is now an MCP server.** An agent in your own client connects with a URL and one browser click: the client discovers the authorization server, registers itself, and a person approves a single consent screen naming the app, the account and the workspace. Sign-in is your workspace's own SSO identity provider. From there that agent can author requirements, personas, scenarios and judges, wire grading where a run actually reads it, launch an evaluation, watch it without spending its whole context, and adjudicate the result — without opening the product. The consent screen offers three answers: **Read only**, **Read and write**, or **Read and write, act mode**, where writes execute without a prompt per change. A client can ask for read and write; it can never demand or escalate itself into act mode, which is a different grant from the Trust Agent's own **Act** mode and implies nothing about it. The token is revocable and a caller can list and delete its own. Two limits are worth stating plainly: parity with the REST authoring surface is deliberately incomplete and enumerated rather than left to be discovered, and there is no in-app screen for managing tokens yet. See [MCP integration](/concepts/mcp-integration).

  **"Couldn't test" is a first-class evaluation outcome, and it is on by default.** A conversation whose own agent action threw used to be graded like any other — and if the agent recovered on a later turn, that conversation could pass. It now reads amber as **Couldn't test** and leaves the pass rate's denominator. Exclusion is not attribution: five outcomes now leave the denominator, and only four of them are the environment's fault, so the grey "not the agent's fault" framing never appears on the agent's own error. The run list carries an amber count beside the pass rate so a green rate never renders uncaveated; Run Detail gains a health strip and a **What happened in this run** dialog; and the Result fly-in gains a banner, a drill-down into the failed action, and a red failed-step pill in the transcript. The vocabulary is frozen to three terms — **Couldn't test**, **Not scored** and **Unverified**. See [Evaluations](/concepts/evaluations).

  **The Requirements list gets the table controls its siblings already had.** Show and hide columns, reorder them, resize them, save a view, set a view as your default, and open the table fullscreen — and returning to the page lands you on that default. The saved-view model is three fixed chips, **All**, **Gaps** and **Failing**, with *All requirements* as the only seeded built-in. Two controls that accepted a click and did nothing were removed. See [Requirements](/concepts/requirements).

  **A hands-on pass on the Trust Agent, and two evaluation corrections.** The Trust Agent now asks for a connected, runnable agent before it authors scenarios or evaluators, rather than discovering the gap after every earlier write has landed, and its single next-step suggestion follows the project's state instead of a fixed script. Human-in-the-loop continuation is restored after questions, approvals, sign-in returns and agent selection. Separately, how many conversations a run drives at once is now a per-run cap over a per-connection default, with a customer-safe Salesforce default and an enforced ceiling; and evaluator accuracy was reading the wrong conversation on scenario-based runs, so it now reads each result's own generated conversation and says plainly that it grades LLM judges against human labels and excludes structural checks.

  **Built, and not yet switched on.** Automatic Full Run — approve once, close the tab, and come back to a project holding requirements, scenarios, judges and a scored evaluation — landed complete and is off by default; nothing about it changes for you in this release. **Download PDF** was removed from the evaluation run page; CSV export is untouched. And four compliance controls now produce dated, executed evidence on a schedule, with static analysis and dependency scanning running against application code for the first time.
</Update>

<Update label="v2026.08.24.1 — August 2026">
  **One Connections tab, and it is what every build serves.** Project settings used to offer two tabs that both claimed the word "connection" and split what you wanted unpredictably across them. There is now a single **Connections** tab — the settings strip reads **General**, **Connections**, **Members** — and links to either retired tab land on it. Each agent the project tests is a card, and **Customize environment** extends that card downward in place, holding its test data stores, its reset behaviour as a plain sentence, how many tests may run at once, and its optional test users. See [Projects](/concepts/projects).

  **A connection card answers two questions, in two vocabularies.** Whether setup is finished reads **Setting up**, **Needs admin** or **Setup failed**, and shows only while setup still has something to say. Whether TrustAI can reach the connection right now reads **Connected**, **Partly reachable**, **Can't reach it** or **Not checked yet** — an unchecked connection says so rather than being painted green. The workspace admin tab that manages your org authorizations is now **Connected orgs**, so the two surfaces no longer compete for one word. And the identity a test runs as is named plainly: **Default test user**, with **Additional test users (permission sets)** beneath it.

  **Stop a Trust Agent turn you no longer want.** A **Stop** control appears while a turn is genuinely running and halts the reply immediately, instead of letting it run to its iteration cap. The turn ends cleanly, and the transcript carries the same calm note a disconnect gets — *"This reply was interrupted."* with **Continue** — so you can pick it back up. See [Trust Agent](/concepts/trust-agent).

  **Salesforce records render as records, and personas stop handing over the answer.** Any record a Salesforce agent returns now renders as a labelled card — Case, Contact, Order, or an object nobody wrote code for — because it is projected by its shape rather than by a key someone remembered to list. A list of records renders as compact cards capped at ten, with a closing line saying how many were left out; a single record still renders whole. Separately, a simulated customer whose goal asked it to verify a fact was stating that fact in its own question, and the agent's echo was counted as confirmation — which quietly inflated goal-met rates. It no longer does. Agentforce profile capture also now works on the authorization every real connection uses, and captures each action's input schema where the org declares one.

  **Every permission refusal names your role, the action, and the remedy.** *"Your Viewer role doesn't have permission to delete personas. Contact a project admin to change your role."* — no identifiers, no internal slugs. Behind it, the project role ladder is complete: Editors own the whole authoring loop, delete included, across personas, evaluators, scenarios and requirements; **Admin** is now a grantable project tier; and ownership is a single seat that moves through its own transfer path rather than through a grant, with project deletion gated on it. See [Multi-tenancy](/concepts/multi-tenancy).
</Update>

<Update label="v2026.08.19.2 — August 2026">
  **A simulated conversation says why it ended.** Two simulated sessions could look identical in the transcript column and mean opposite things — the customer got what they needed, the customer gave up, or the run reached its length limit mid-conversation. A conversation now closes with one plain sentence beginning *"This conversation ended because "*, and where the simulated customer explained itself, its own words are shown verbatim rather than flattened to a label. A conversation with no recorded ending renders nothing at all — no "Unknown", no placeholder. See [Sessions](/concepts/sessions).

  **A picture the agent can't accept says so in one sentence.** Attaching an image to a Salesforce agent whose org lacks the entitlement used to dump the raw vendor response at whoever attached it; it now reads *"This agent doesn't support uploads of this type."* The refusal itself is unchanged — the turn still fails and the message is still never sent. Separately, one component failing no longer blanks the whole app: the failed page is replaced on its own, with the shell, navigation and agent dock left standing.
</Update>

<Update label="v2026.08.19.1 — August 2026">
  **A conversation can carry a picture.** Attach a picture in the [Playground](/concepts/playground), with or without a caption, and the agent under test receives the actual image rather than a file name — an image-only message is a first-class turn. The picture survives the request that carried it: the transcript renders it in the bubble, and a click opens it full-window, in the Playground and on the session panel alike. Accepted formats are **PNG**, **JPEG**, **WebP** or **GIF**; a connector that does not accept pictures runs the conversation as text instead of failing the whole evaluation; and when a picture cannot be shown, the chip says which case it is — never saved with the conversation, or saved but not loadable.

  **Scenarios can carry pictures too.** Add files in the scenario editor and describe what each one shows; the simulated user reads the conversation and decides for itself which picture helps and when, reasoning from your description rather than from the image. Saving a Playground conversation as a scenario now brings its pictures across, oldest first, and names any that stayed behind and why. Two limits are worth knowing: the AI judge still cannot see a picture, so grade what the agent did about it rather than the image itself; and where you leave a description empty, the system writes one when the simulation runs but never shows it to you.

  **Adopting the recommended security scenarios can tailor them to your agent.** The adopt dialog now offers **Add & tailor to your agent** alongside **Add without tailoring**. Tailoring completes the adoption immediately and then runs unattended in the background — keeping the adopted checks where they already grade well, tailoring judges where your agent declares its own rules, and pinning hard disallowed-action contracts where an attack aims at a capability your agent really has. With no agent connected, the primary action disables under **Connect an agent to tailor these**; adoption itself never blocks. See [Scenarios](/concepts/scenarios).

  **A turn that fails now says so.** Where the thinking dots used to stop into dead air, the thread paints a card carrying one plain sentence, the hint *"You can try again, or pick a different model first."*, a **Try again** action and the model picker. The raw exception is never shown. The turn is stored as failed rather than saved as a clean success, and a run that produced no reply is not billed. See [Trust Agent](/concepts/trust-agent).

  **Requirements is on by default.** The tab had been invisible on every deployed environment since the surface shipped — it went in behind a dark-launch flag while it was still a stub, and nothing ever opted in. It is on. Two repairs ride along: an Agentforce profile can no longer come back empty and still report success, and production had been serving every page load with its clickjacking, MIME-sniffing and referrer protections silently stripped. All three are restored. See [Requirements](/concepts/requirements).
</Update>

<Update label="v2026.08.14.1 — August 2026">
  **The Trust Agent sets a Salesforce project up for you.** Connecting an org now starts a background read of the agent's make-up — its topics, its actions, and the operating rules its own platform declares — so the profile is captured while you carry on. A brand-new project leads its suggestion row with **Show me where to start**, and the walk that chip pre-fills reads where the project actually is on every turn, names the single next step, and resumes from the project's own records when you come back days later rather than from a conversation it no longer has. When it is time to file requirements, the agent drafts a curated list from what your connected agent actually does and files the whole batch behind one approval card that names every record. See [Trust Agent](/concepts/trust-agent).

  **Chat gains model choice and a thinking depth.** The model a turn runs on is now yours to pick, on the new-chat launcher or in the composer, and your choice survives a reload. A **Thinking** chip sets how deeply the agent thinks per message — **Standard**, **Brief**, **Balanced** or **Thorough** — offering only the depths the selected model declares, and hiding entirely for a model with one. Each depth is its own model's scale, not a ranking across vendors, and which models a given deployment serves is a deployment decision. Every settled reply now carries a timing line in the shape *"Answered in 42s · 31s thinking"*, collapsed by default and expanding into per-phase totals; under a second it reads *"Answered in under 1s"*.

  **Adopted scenarios arrive graded, and the judge reads the whole conversation.** Adopting recommended scenarios used to create scenarios with no checks attached, so ten adopted probes graded nothing. The batch now lands as one action that creates each scenario, creates any missing paired safety check once even where two scenarios share it, and attaches them — so the first run produces verdicts instead of blanks. Renaming an adopted scenario no longer resurfaces it as un-adopted, and the Quality preset that checked for hallucination is now **Internally consistent**, narrowed to what a transcript can actually prove, for newly adopted copies. Underneath all of that, the AI judge had only ever been reading the agent's closing reply — so an agent that broke a guardrail on turn 2 and recovered by turn 5 passed. It now reads the whole conversation, and a criterion violated on any turn fails it. See [Evaluators](/concepts/evaluators).

  **A run says how it ended.** In a project with no evaluators, a graded run and a deliberate simulation rendered as the same screen, and both read "Not graded". The header now splits into three honest endings: **Run only — nothing was graded** for a simulation you asked for, **Not graded — no evaluators** for a graded run that had nothing to grade with, and the ordinary graded view otherwise. Runs recorded before this keep neutral wording rather than claiming an intent the record cannot evidence. Salesforce sessions also now carry the org's own evidence — its turn-by-turn grading of its agent with the reasoning it wrote, the moments the agent paused for approval, and full model-call detail — and routing checks grade against what was actually captured. See [Evaluations](/concepts/evaluations).

  **Test data is on by default, and every credit has a real cost behind it.** A deployment that configures nothing now gets the test data surfaces; disabling them is the explicit choice. Connecting a Salesforce org through the one-click flow can seed, read and reset test records straight away by reusing the identity of the admin who authorized it, while naming a dedicated test user stays fully supported for teams that want stricter separation. Separately, every metered action now records its actual cost instead of a flat credit — which corrected a roughly tenfold under-bill on long Trust Agent turns — and evaluation spend is credited to the person who launched the run rather than to an unattributed background bucket. See [Track credit usage](/how-to/track-credit-usage).
</Update>

<Update label="v2026.08.03.1 — August 2026">
  Salesforce runs now grade on evidence captured while the turn is happening.

  **Evidence is captured in-turn, not polled after.** TrustAI used to drive a Salesforce conversation and then poll an eventually-consistent trace export to learn what the agent did — so you could finish a run and still not know whether your agent called the right actions. The runtime now reads the planner's own account of each turn as the turn completes, and grading uses that. The OpenTelemetry session trace still publishes on Salesforce's own schedule (typically ~11–13 minutes after a session ends) and remains available for deeper inspection; a banner tells you when it has not landed yet rather than showing you a blank.

  **The Groundedness judge takes its final name.** The claim-grading judge introduced in v2026.07.26.1 is now called **Groundedness**, and its result chip reads *N% grounded*. See [Evaluators](/concepts/evaluators).
</Update>

<Update label="v2026.07.26.1 — July 2026">
  **Grade answers against the material they should have come from.** A new **Groundedness judge** checks whether an agent's factual claims are supported by source material you supply. Attach the articles, policies, or knowledge a scenario should be answered from as **Reference material** on that scenario's Expected Output — up to five documents — and every factual claim in the agent's replies is graded against them.

  Each supported claim carries a verbatim quote that the system verifies against the document, so the evidence is checkable rather than asserted. Claims are labeled **Supported**, **Contradicted**, **Unsupported**, **Unknown**, or **Conversational**, and a reviewer can override any per-claim verdict with a note — the score recomputes. Grading is strict: a single unsupported factual claim fails the check.

  The judge does not penalise omissions, tone, style, or formatting — it answers one question, whether what the agent said is backed by what you gave it. See [Evaluators](/concepts/evaluators).
</Update>

<Update label="v2026.07.18.1 — July 2026">
  **Connect and evaluate a live Salesforce Agentforce agent — without handing over a secret.**

  Connecting an Agentforce org is now a two-step authorization: give TrustAI your org URL, authorize once in Salesforce as an administrator, then pick the agent and the user it should run as. <Update label="v2026.07.16.1 — July 2026">
  **Agent Profile: see what a connected agent can actually do.**

  TrustAI now captures a connected agent's real capabilities — its tools with their exact input schemas, its knowledge sources, and where each fact was observed — into a versioned, human-reviewable profile. A profile belongs to one agent version, so it is a record of what that build could do, not a moving picture.

  Open it from the Playground topbar or a connection's **Current agent version** row. Discovery coverage reads **Captured**, **Partial**, or **Limited** per dimension, and every source reports its own state — **Available**, **Not exposed**, **Not sampled**, or **Not run** — so an absence is always named rather than silently blank. Where the automatic capture is wrong or incomplete, correct it with an overlay that survives regeneration, then record **Approve** or **Request changes** against that revision.

  Capability discovery currently reaches Conversational HTTP, Claude Managed Agent, and Salesforce Agentforce connections. Others report that profiling is not available for them yet.

  A pinned profile also grounds the Trust Agent: when it drafts expected output for a scenario, the tools it can reference are the ones your agent actually has.
</Update>

<Update label="v2026.07.08.1 — July 2026">
  A large release with two independent headlines: the Trust Agent becomes something you can connect, watch, and improve from inside the conversation, and evaluation authoring moves further into plain language.

  **Connect an agent from inside the chat.** Ask the [Trust Agent](/concepts/trust-agent) to connect your agent and it handles the whole exchange in a secure in-chat card — credentials are write-only and never read back. Once connected, a **Connected agent** card sits at the top of the conversation's Context rail with a live health state: **Not checked**, **Healthy**, **Degraded**, or **Unreachable**.

  **Skills: reusable recipes the agent can run.** The Trust Agent's repeatable procedures are now visible and editable. Built-in skills ship with the product and are read-only; workspace skills are authored by your admins and available to everyone in the workspace. When the agent uses one, the transcript shows a receipt naming the skill, so you can see which recipe produced a result. Skills live in Workspace Settings.

  **The Trust Agent can author expected output.** Ask it to write a scenario's grading contract and it proposes one in plain English — what the agent must do and must never do — for your approval before anything saves. Expected actions are checked against the tools your connected agent actually has, so it cannot invent a capability.

  **Human-in-the-loop approvals become durable.** An approval you were asked for survives reload and disconnect, and comes back answerable. You can also grant a **standing approval** for a kind of action for the rest of a conversation, and turn it off at any time from the chip in the transcript. Irreversible deletes are always excluded. See [Approve agent writes](/how-to/approve-agent-writes).

  **Usage caps for pilot workspaces.** Workspaces on a credit pool can see what they have used against it in Workspace Settings → **Credits**, with a breakdown of where the credits went. The pool resets monthly. When a workspace reaches its limit, runs are blocked with a clear message rather than failing obscurely.

  **Scenarios absorb the last of the dataset container.** The legacy `/v1/datasets` API is retired; scenarios carry their own columns, rows, tag vocabulary, and CSV import and export directly. See [Scenarios](/concepts/scenarios).

  **Requirements.** Capture what your agent must do — and must never do — in business language, then link each requirement to the scenarios and evaluators that prove it. Every requirement carries a plain handle like `REQ-12` and a computed health rollup: **Passing**, **Failing**, **Partially covered**, **Uncovered**, or **Not yet run**. Gaps are the requirements nothing covers yet, so you can see where your test suite is thin rather than guessing. Requirements can be written by hand, extracted from a document, or captured from a conversation with the [Trust Agent](/concepts/trust-agent).

  **Test data.** Grade an agent on the backend state it actually leaves behind, not just what it said. Register environments and data connections, author the starting data a scenario runs against and the end state it should reach, then read a per-record expected-versus-actual diff and a change ledger alongside the conversation. Proven across Salesforce Agentforce, AWS AgentCore, and Claude-managed runtimes.
</Update>

<Update label="v2026.06.30.1 — June 2026">
  The headline of this release: the evaluation product is re-rooted on a flat, first-class **Scenario**. Around it land a Trust Library so new projects don't start from a blank slate, no-code evaluator tailoring, a guided Trust Agent cold start, an overhauled Sessions review surface, and a test data preview.

  **Scenarios are a first-class surface.** One flat, searchable [Scenarios](/concepts/scenarios) list replaces the old data-rows view — scenario sets are gone — with stable ids like `SCN-000123`, safe delete that blocks anything still referenced by an evaluation, and inline editing for names, goals, personas, and evaluators. Every scenario opens into a two-level fly-in: personas and goals, the **Expected Output** editor — where you define the grading contract from vocabulary the product learned from your real sessions — and the scenario's linked sessions, with a nested panel to drill into any single session. On the wire, a `/v1/scenarios` family joins the API; `/v1/datasets` remains the legacy container API underneath.

  **One Evaluation Launcher, five doors.** Every run now starts from the same launcher — bulk from Scenarios or Sessions, one-off from either fly-in, or fresh from Evaluations — with a fan-out preview before you commit and a **Re-run** that faithfully restores a run's full configuration. Scenario runs simulate a fresh conversation per persona; session runs grade the conversations you already have. Results lead with a dual headline — how often the agent passed, and how often the automated judges agreed with a human — plus a per-persona matrix with plain-English divergence hints. See [Evaluations](/concepts/evaluations).

  **Evaluate real conversations.** [Sessions](/concepts/sessions) are now first-class evaluation targets: a primary **Evaluate** action grades captured conversations with your AI-judge evaluators (the old "Add to dataset" detour is retired), each session carries a Source chip — **Scenario**, **Playground**, or **External** — and "Open session" on any result lands you on the exact conversation it graded.

  **Grade sessions in place.** Reviewers get typed [annotation columns](/concepts/annotations) on Sessions — pass/fail verdict, severity, score, tags, and reviewer notes — editable inline in the table or in the fly-in. A person's verdict is the ground truth that evaluator accuracy is measured against; it never overrides the automated verdict.

  **Trust Library.** Adopt 12 recommended evaluators (six Quality, six Safety, each a plain-language judge with a provenance chip) and 10 starter safety scenarios mapped to the OWASP Agentic AI Top 10 — in one move, from the [Evaluators](/concepts/evaluators) library or a cold-start empty state. Everything adopted is an ordinary, fully editable object. *(Superseded: the recommended catalog is now 11 evaluators — 5 Quality and 6 Safety. "Answer is grounded" was withdrawn, since as a plain judge it was never handed the source material it claimed to check; the [Groundedness judge](/concepts/evaluators) added in v2026.07.26.1 does that job properly. A couple of presets score on a 1–5 scale rather than pass/fail.)* *(Superseded in v2026.08.14.1: adopting recommended scenarios now creates and attaches their paired safety checks, so an adopted suite grades from its first run, and the Quality preset that checked for hallucination is now **Internally consistent**. "Trust Library" was never a label in the product — the shipped entry points are **Add recommended evaluators** and **Add recommended scenarios**.)*

  **Define pass and fail in plain language.** LLM-judge evaluators gain a **Passes when / Fails when** rubric editor — short sentences instead of judge prompts, quietly assembled back into the exact criteria the live judge uses so verdicts never shift — and a **Tailor with AI** box drafts the rules from a one-line goal plus a description of your agent, for you to review before anything saves.

  **The Trust Agent walks you from zero to first eval.** A brand-new user is guided end to end in one conversation: connect an agent, run an observe-only exploration that watches behavior without scoring it, accept proactively drafted behavior and security coverage, and get a first scored evaluation. One-tap next-step chips pre-fill (never auto-send) the composer, and the Welcome screen's starter prompts adapt to your setup state. See [Trust Agent](/concepts/trust-agent).

  **Reliability under load.** Bulk runs ride out model-capacity throttling with automatic retry and backoff, live per-scenario progress badges keep you on the list while forty runs settle, one bad row can't sink a run, and a judge call that can't complete is set aside as an environment problem — a capacity hiccup never masquerades as a drop in agent quality.

  **Access Center, refined.** The workspace admin surface consolidates six tabs into four (Members, Teams, Project access, General); the full roles-and-permissions matrix now appears inline at the moment you assign a role, and access history is an in-context drawer. *(Superseded in v2026.08.24.1: the workspace admin surface has six tabs, and the fifth is **Connected orgs** — the Salesforce org authorizations a workspace holds. **Connections** now names the project settings tab listing the agents one project tests.)*

  **Test data (preview, off by default).** Behind a preview flag: register environments and data connections, author per-scenario starting data and the end state a run should reach, then grade the agent on the backend state it actually leaves behind — a five-dimension verdict matrix (Safety, Outcome, Quality, Behavior, End state) with a per-record expected-vs-actual diff and a change ledger. The loop is proven across Salesforce Agentforce, AWS AgentCore, and Claude-managed runtimes. Preview surfaces are flag-gated and off by default in production builds. *(Superseded: test data is no longer a preview — it is enabled and generally available. See the v2026.07.08.1 entry above.)*

<Update label="v2026.06.22.1 — June 2026">
  This release brings the evaluation loop's first transparency surfaces, a far more livable Trust Agent chat, and an enterprise-readiness track: workspace administration, a unified authorization engine, and a Salesforce Agentforce connector.

  **Calibrate: measure how much to trust an AI judge.** LLM-judge [Evaluators](/concepts/evaluators) gain a Calibrate tab: point the judge at labeled scenarios carrying your own pass/fail verdicts and see a plain-English agreement score — computed by the exact judge your evaluation runs use, so the number you see is the number you'll get. A disagreement-first table shows where you and the judge part ways, and calibration history tracks agreement as you tune the rubric.

  **Pass^K reliability scoring.** A "Repeat each test case" control on the run form runs every case up to four times, and a finished run leads with how often the agent passed **all** attempts — surfacing flaky agents a single run hides (an agent that looks 87% reliable on one attempt may pass all four only 31% of the time). New runs default to Pass^2. See [Evaluations](/concepts/evaluations).

  **Trust Agent chat comfort pass.** Unsent drafts survive navigation, an Attach button brings PDF, Word, text, CSV, JSON, and Markdown files into the conversation with side-rail previews, long messages collapse behind Show more, an interrupted reply reopens with a one-tap Continue, and the Plan / Context / Outputs rail stays put across the whole conversation. See [Trust Agent](/concepts/trust-agent).

  **Full agent traces.** Transcripts now show what the model was thinking ("Thinking" steps) and what each model call asked and answered, in plain language, across replay transcripts and the live Trust Agent. Reasoning is provider-dependent — it appears where the runtime supports it and degrades to an honest "not available" state elsewhere, never a blank frame. See [Sessions](/concepts/sessions).

  **The Trust Agent drives the scenario loop end to end.** Ask it to generate scenarios and it proposes persona-and-goal test cases; run an evaluation with simulation and it plays out a fresh multi-turn conversation for every persona against your live agent and scores those real transcripts. The old generate-static-sessions detour — and its tool — is gone. See [Scenarios](/concepts/scenarios).

  **Access Center: no-code workspace administration.** Owners and admins invite members and manage the full invite lifecycle, group people into teams, grant per-project **Viewer**/**Editor** access directly or through a team, and audit who-can-reach-what with plain-language provenance. Underneath, a single FedRAMP-ready authorization engine now governs every access decision and writes each one to a durable, append-only audit trail. See [Multi-tenancy](/concepts/multi-tenancy).

  **Salesforce Agentforce connector.** Connect an Agentforce org with JWT-bearer credentials from Settings and drive a live agent through evaluations. *(Superseded in v2026.07.18.1: new Agentforce connections are made by authorizing TrustAI once as a Salesforce administrator — no certificate to generate or hand over. The certificate path remains only for connections that already use it.)*

  **Data-table power features.** Drag columns into your own order (remembered per [saved view](/concepts/saved-views)), shift-click to select a whole range of rows, and a single unified column menu replaces the duplicate gear icons — across Sessions, scenario detail, and run detail tables.

  **Security.** Host connection secrets — Salesforce private keys, AWS access keys, and managed-agent API keys — are now masked in every API response; the UI still shows whether a connection is configured.
</Update>

<Update label="v2026.05.19 — May 2026">
  **API surface additions.** Eleven new endpoints land across Projects, Agent Versions, Datasets, Evaluators, and Evaluations:

  - **Projects** — `GET /v1/projects/{id}/requirements` lists configured requirements for the Project.
  - **Agent Versions** — `GET /v1/agent-versions/run-options` surfaces the runtime invocation options each connected platform supports.
  - **Datasets** — five additions: `POST /duplicate` clones a Dataset for variant experiments; `GET /export.csv` downloads the Dataset; `GET` and `PUT /tag-vocabulary` define and inspect the controlled tag set; `GET /columns/{key}/option-usage` reports per-option frequency for enumerated columns.
  - **Evaluators** — `GET /v1/evaluators/{id}/ref-check` lists the Datasets and Evaluations currently referencing an Evaluator (recommended before archiving or rubric-breaking edits). Request-body type for `PATCH /v1/evaluators/{id}` renamed from `UpdateEvaluatorInput` to `EvaluatorPatchRequest` — route is unchanged, only the schema name moved.
  - **Evaluations** — `POST /v1/evaluations/{id}/cancel` halts an in-progress run; `GET /v1/evaluations/stats` aggregates pass-rate and latency trends across the Project; `POST /v1/evaluations/cohort-breakdown` slices a run's per-row results by intent, tag, or custom dimension.

  **Saved Views.** A new `/v1/saved-views` endpoint family lands with `POST /v1/saved-views/{id}/default` to mark a view as the user's default for a list surface. Saved Views are not yet covered in the Concepts section; expect a dedicated page in a future docs release.
