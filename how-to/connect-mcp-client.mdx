Trust AI runs an [MCP server](/concepts/mcp-integration) that republishes a small, fixed subset of the **Trust Agent's** tools. This page is about the client side of that: pointing a standalone MCP client — Claude Desktop, Cursor, a VS Code MCP extension — at it.

<Warning>
  **Connecting your own MCP client is not yet supported.** There is no supported way to point an external client at Trust AI, and no MCP configuration screen anywhere in the product. The server authenticates every call on a signed-in Trust AI session, and reaching it that way from outside the product is an internal path only — not a customer integration, and not something to build against.
</Warning>

## What "not supported" means here

It is a statement about what Trust AI stands behind, not a claim that the mechanism is missing.

**What is missing is a credential you can hold.** Every authenticated request Trust AI accepts — over MCP and over the REST API alike — is authorized by your signed-in browser session. There is no key Trust AI issues to a client, so there is nothing you could scope to read-only, rotate on a schedule, or revoke when a laptop goes missing. That, not the protocol work, is the gap.

**So there is nothing to configure.** No connection screen, no server address to paste, no per-client snippet for us to publish. A path we supported would need an issued, revocable credential in place of a session. That is a design direction, not a scheduled release, and this page will not guess at a date.

<Note>
  Earlier versions of this page said the standalone-client path would arrive with an OAuth sign-in flow, and that a client would be handed a short-lived token automatically. That was wrong on both counts. **No OAuth work is planned**, and nothing described here is waiting on it.
</Note>

## Use the Trust Agent instead

Nothing sits behind the unsupported door that the product does not already give you. MCP does not add capability — it republishes the Trust Agent's own tools over a second transport, running the same implementations. The agent inside Trust AI is the full surface, not a subset of it, and it reaches you with no client configuration at all.

Open a chat from any project and ask for the work directly:

- **Get oriented** — "Summarize this project" returns entity counts, setup state, and the most recent evaluation run.
- **Query your data** — "How many sessions are in this project?", "Show me two sessions from this project." One entity type at a time: sessions, scenarios, evaluators, evaluations, personas, agent versions, or [requirements](/concepts/requirements).
- **Read an attached file** — attach a document to the chat and ask the agent to read it back.
- **Analyze a run** — "Analyze the failures in the last evaluation" produces a short note on each failure and then names the themes across them. It typically takes 30 to 60 seconds.
- **Write, with a checkpoint** — curating conversations into scenarios, editing or deleting an item, and starting an evaluation each preview what would change and then wait for you to approve. A one-time approval covers that write alone. Where the card also offers a for-this-chat scope, approving it grants a standing pass and the agent repeats that kind of write for the rest of the conversation without stopping again — deletes never offer it, so every delete is approved on its own. See [Approve an agent write](/how-to/approve-agent-writes).

[Work with the Trust Agent](/how-to/work-with-the-trust-agent) covers the chat surface itself — the Ask, Plan, and Act modes and how approvals are granted.

## If what you wanted was to connect your own agent

Connecting the agent you want to evaluate is a different job, and it is supported. It runs through a platform connection, not through MCP. **Four platforms are connectable.** Three have a guide of their own:

- [Connect an AWS Bedrock AgentCore agent](/how-to/connect-agentcore)
- [Connect a Salesforce Agentforce agent](/how-to/connect-agentforce)
- [Connect a Claude Managed Agent](/how-to/connect-claude-managed-agent)

The fourth is the **Conversational HTTP agent** — any agent that accepts run requests and streams responses back over HTTP, on no named vendor platform at all. It has no guide of its own yet. Add it the same way as the three above: **Project settings → Connection → Add connection**, then pick it from the platform list. If you came here because your agent does not run on one of the named platforms, this is your path, and it is the closest thing to "point your own thing at Trust AI" that is supported today.

Your agent under test may itself speak MCP to its own tools. That relationship is between your agent and those tools; it is unaffected by anything on this page.
