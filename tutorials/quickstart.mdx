This tutorial walks you from a brand-new Trust AI account to your first scored evaluation of a real agent, in roughly ten minutes. It assumes you're setting Trust AI up for a customer agent for the first time; the shape is the same when you add a new agent to an existing workspace.

Most of these steps you'll drive by asking the [Trust Agent](/concepts/trust-agent) — the in-app assistant — in plain language, then watching the results land in the UI. Where you'd rather do something by hand, the manual UI path is right there too. On a brand-new project the Trust Agent is taught exactly this arc — connect, explore, create coverage, evaluate — so you can also just follow its lead.

By the end you'll have:

- A [Project](/concepts/projects) connected to your agent's platform
- Real [Sessions](/concepts/sessions) you can read end to end
- Starter [Evaluators](/concepts/evaluators) and [Scenarios](/concepts/scenarios) adopted from the Trust Library
- One scored [Evaluation](/concepts/evaluations) run you know how to read

That's one complete pass through [the evaluation loop](/concepts/evaluation-loop). Once it works once, the rest of Trust AI is "do this same thing at scale."

## Before you start

You'll need:

- A Trust AI account with access to a workspace where you can create projects
- An agent on one of the four platforms Trust AI connects to — **AWS Bedrock AgentCore**, **Salesforce Agentforce**, **Claude Managed Agent**, or a **Conversational HTTP agent** — plus its connection credentials, or an admin who has them
- About 10 minutes

<Tip>
  **No credentials at hand?** Start anyway. When you ask the Trust Agent to connect your agent, it hands you a plain-English checklist of exactly what to gather — something you can forward to your admin. For AgentCore, the setup wizard produces an admin handoff package your AWS admin can deploy without you.
</Tip>

## The six steps

<Steps>
  <Step title="Create your first project">
    A [Project](/concepts/projects) is the workspace boundary around one agent under evaluation. Members, connections, and every artifact downstream belong to it.

    Creating a Project is the one setup step you do before the Trust Agent comes into play — the conversation lives *inside* a Project, so you need one first. Open the project switcher at the top of the sidebar and click **Create new project** (on a workspace with no projects yet, you'll land on a **Create your first project** screen with a **New project** button instead). Name it after the agent under evaluation (e.g., "Acme Support Agent") — a description is optional — and click **Create project**.

    **You should see:** you land inside the new Project. The left nav shows its surfaces, top to bottom: **New chat**, **Playground**, **Requirements**, **Scenarios**, **Sessions**, **Evaluators**, **Evaluations**, and **Project Settings** — all empty for now. Requirements, Scenarios, Sessions, Evaluators, and Evaluations each carry a count badge, reading 0 on a new project.
  </Step>

  <Step title="Connect your agent">
    Click **New chat**. On a brand-new project, the welcome screen shows four category pills that trace this exact tutorial: **Connect agent**, **Explore behaviour**, **Create scenarios**, and **Run evaluation**. Clicking a pill expands three suggested prompts underneath it; clicking one of those pre-fills the message box — nothing sends until you do.

    <Note>
      *Ask the Trust Agent:* "Help me connect the agent I want to test."
    </Note>

    The agent first checks whether an agent is already connected. If not, it opens a secure connection card **inside the chat** for either **Salesforce Agentforce** or **Claude Managed Agent**, and the connection completes there — you never leave the conversation. The card collects credentials directly; your key or secret is never shown to the model and never appears in the transcript. Once it resolves, the card's receipt names the agent you connected.

    For Salesforce, that card is a short guided wizard: confirm your org, choose **Authorize TrustAI (recommended)**, approve TrustAI in Salesforce with an administrator account, then pick the agent to test.

    Prefer the manual path, or connecting **AWS Bedrock AgentCore** or a **Conversational HTTP agent**? Open **Project Settings**, switch to the **Connection** tab, and click **Add connection**. The picker offers four platforms:

    - **AWS Bedrock AgentCore** — a guided setup wizard: prepare an admin handoff package, have your AWS admin deploy the cross-account role, then paste the role ARN back. Full walkthrough: [Connect an AWS Bedrock AgentCore agent](/how-to/connect-agentcore).
    - **Salesforce Agentforce** — a two-step flow. Enter your org's URL, then click **Authorize in Salesforce with an administrator account**; Salesforce opens in a new tab and the connection is set up for you when the admin approves. Step two is picking the agent to test. Full walkthrough: [Connect a Salesforce Agentforce agent](/how-to/connect-agentforce).
    - **Claude Managed Agent** — a form for an Anthropic Managed Agent on Claude Platform on AWS. Full walkthrough: [Connect a Claude Managed Agent](/how-to/connect-claude-managed-agent).
    - **Conversational HTTP agent** — for any agent that accepts AG-UI run requests and streams AG-UI events over SSE. Use this when your agent isn't on one of the named platforms. Full walkthrough: [Connect a Conversational HTTP agent](/how-to/connect-http-agent).

    <Warning>
      The Salesforce authorize step deploys a connected app into whichever org you sign in to. Point it at a Sandbox, not production.
    </Warning>

    Secrets are write-only throughout — once saved, Trust AI shows a **Configured** pill and the placeholder `•••• configured — leave blank to keep existing`, never the value back.

    **You should see:** your agent listed as a connection on the **Connection** tab, with its current agent version named underneath.
  </Step>

  <Step title="Observe real sessions">
    With the agent connected, pull in the conversations it's already having.

    <Note>
      *Ask the Trust Agent:* "Pull in some of my real conversations so we have material to work from."
    </Note>

    Or do it by hand: open **Sessions** and click **Sync now** — it opens a per-agent picker, so choose your connected agent. Conversations pulled from your platform land in the list. By default the list shows **Session ID**, **Transcript**, **Routed To**, **Tools Called**, **Turns**, **Date**, and **Verdict** — the reserved human Pass/Fail column every project starts with. **Source** is one of the columns you add from **Add column**, and it reads exactly one of **Scenario**, **Playground**, or **External** (see [Sessions](/concepts/sessions)).

    Click any Session to open it. The fly-in leads with the full **Transcript** — every turn, tool calls included — plus tabs for **Annotations**, **Evaluations**, and **Details**. Read one end to end; this is the raw material everything downstream grades. A session nothing has scored yet reads **Not evaluated**.

    <Tip>
      **Agent has no traffic yet?** Ask the Trust Agent: "Try my agent with a few example questions and show me how it responds." It runs one open-ended conversation against the live agent and summarises what the agent is for, what it can do, the tone it takes, and where its guardrails sit. Nothing is graded — the point is to understand the agent first-hand before you define what "good" means.
    </Tip>

    **You should see:** the Sessions list populated, and at least one Session you've read end to end.
  </Step>

  <Step title="Adopt starter evaluators and scenarios">
    A new project doesn't start from a blank slate: the Trust Library ships curated defaults you can adopt in one move, and the Trust Agent can draft coverage specific to your agent.

    <Note>
      *Ask the Trust Agent:* "Generate a first set of test scenarios for my agent." Then: "Add some security scenarios that probe for unsafe or off-policy answers."
    </Note>

    The agent proposes [Scenarios](/concepts/scenarios) — each a persona plus a goal, the test cases your evaluations will run — and pauses with an approval card showing exactly what it will create before anything is saved. Approve, and they land in your Scenarios list.

    The manual path is the Trust Library:

    - On **Evaluators**, click **Add recommended** to adopt from the 11 recommended [Evaluators](/concepts/evaluators) — **5 Quality** and **6 Safety** presets. Most return a pass/fail verdict; two of the Quality presets ("Answer is complete" and "Accomplished the goal") score on a 1–5 scale instead. Tick the ones you want; the confirm button names how many you've picked.
    - On **Scenarios**, click **Add recommended scenarios** to adopt from the 10 starter safety scenarios — one per failure mode in the OWASP Top 10 for Agentic Applications.

    Everything you adopt becomes an ordinary, fully editable evaluator or scenario — no special status.

    <Tip>
      Writing one from scratch instead? **New evaluator** offers two kinds: **LLM judge** (freeform criteria another model grades against) and **Groundedness judge** (checks every claim against the reference material attached to a scenario's **Expected Output**). Structural checks — **Expected routes** and **Expected actions** — are no longer something you create as an evaluator; they live on each scenario's **Expected Output** tab.
    </Tip>

    **You should see:** the Scenarios list populated, each scenario carrying a stable id like `SCN-000022`, and the Evaluators list showing your adopted judges.
  </Step>

  <Step title="Run your first evaluation">
    Now run those scenarios against your connected agent.

    <Note>
      *Ask the Trust Agent:* "Run my first evaluation against the connected agent."
    </Note>

    By hand: on **Scenarios**, use the **Run** split button (select specific scenarios first, or leave the selection empty to run the current view). Clicking **Run** launches **Run & evaluate**; the chevron beside it exposes both modes explicitly:

    | Mode | What it does |
    | --- | --- |
    | **Run only** | Simulate without grading |
    | **Run & evaluate** | Simulate + grade → creates an evaluation |

    Either opens the launcher, which previews the fan-out before anything starts — how many scenarios, how many conversations will be simulated, and how many evaluator runs that adds up to. Each scenario is simulated once per attached persona, then graded by the evaluators inherited from that scenario. **Repeat each test case** (1–4) reruns every case so you can see how reliably the agent passes. Confirm with **Run evaluation**.

    The same launcher opens from **New evaluation** on the **Evaluations** page, where you additionally choose what to evaluate — **Sessions** (grade conversations that already exist, no simulation) or **Scenarios**.

    You stay on the Scenarios list while the run executes: each scenario shows a live progress badge that settles as it finishes.

    **You should see:** per-scenario badges settling, and a new run appearing on the **Evaluations** page.
  </Step>

  <Step title="Read the results">
    Open the run from **Evaluations**.

    The run header carries the completed count and the date it ran, led by the pass rate — or by **Not graded**, when the run carries no behavioural grade at all. The results body then leads with a single headline stat, **Conversations passed**, e.g. "6 of 10 conversations". That stat reads **Not graded** too, captioned "No conversation has been scored yet", whenever nothing on the run was behaviourally graded — which is exactly what a **Run only** run looks like. Neither place ever shows a fabricated number.

    A second headline, **evaluator accuracy**, appears once you've recorded human Pass/Fail verdicts on sessions — it measures how often the automated judges agree with a person, grading the judges rather than the agent. Until then it is absent from the header entirely, and the **Evaluator accuracy** column on the **Evaluations** list reads as empty.

    Below that is the results table. It opens **By scenario** — one summary per scenario and persona, expandable to its individual attempts. To flatten it, open the **Columns** menu in the results toolbar: the **View** toggle sits at the very top, offering **By scenario** and **Flat**. Each row names the persona that drove the conversation, and carries the **Final verdict** plus one column per evaluator, so you can see *which* check failed and *who* the agent struggled with.

    Open any result to read the full conversation. The transcript labels how the result was produced, and there are exactly two labels: **Simulated** (the run drove a fresh conversation with your agent and scored that) or **Replayed** (the run replayed the scenario's saved input and scored the agent against it).

    And if something outside the agent broke, that result is excluded from the score rather than counted as an agent failure — **Guardrail blocked**, **Environment problem**, and **Access blocked** all sit outside the denominator.

    **You should see:** a scored run with a headline stat, a per-scenario results table, and readable transcripts behind every verdict.
  </Step>
</Steps>

## What Trust AI knows about your agent

Alongside the loop above, Trust AI keeps a read of the agent itself — its **Agent Profile**. Open it from the current agent version row on **Project Settings → Connection**, or from the profile button in the **Playground** topbar. It has three tabs — **Overview**, **Tools**, and **Sources** — and a freshly connected agent starts with none of it: the panel reads "No profile has been generated for this agent build yet" with a **Generate profile** button.

The profile is what makes the Trust Agent's exploration and scenario drafting specific to your agent instead of generic. Note the platform limit: profiling is available for Conversational HTTP, Claude Managed Agent, and Salesforce Agentforce connections. On an AgentCore connection the panel reports that agent profiling isn't available for this connection yet.

## You've walked the loop once

Connect, observe, define coverage, run, read — that's [the evaluation loop](/concepts/evaluation-loop), end to end, once. From here it's depth, not new shape: author expected outputs on the scenarios that matter, tailor the recommended evaluators to your agent's rules, and [record human verdicts on sessions](/how-to/annotate-sessions) so evaluator accuracy has ground truth to grade against.
