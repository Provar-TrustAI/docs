This how-to connects a **Claude Managed Agent** — an Anthropic Managed Agent running on Claude Platform on AWS — to a Trust AI [Project](/concepts/projects). When you're done:

- The agent is registered as an [Agent Version](/concepts/agent-versions) you can pick when you launch an Evaluation
- Trust AI can drive conversations against it — explorations, simulated scenarios, and scored evaluation runs — and each conversation lands in the Project as a [Session](/concepts/sessions)

Trust AI's role with this connector is deliberately narrow: it observes the agent and relays its responses, while the agent runs its own tools. You are not redeploying or reconfiguring the agent — you're pointing Trust AI at it.

There are **two ways to connect**, and they save the same connection:

- **In the chat** with the [Trust Agent](/concepts/trust-agent), through a secure connection card. This is the fast path and the one to reach for first.
- **From the connection form** in **Project Settings → Connection**. Use it when you're already in Settings, or when you need to edit or delete a connection that exists.

<Note>
  Two different "agents" meet on this page. The **Claude Managed Agent** you're connecting is *your* agent — the one under test, tracked as an [Agent Version](/concepts/agent-versions). The **Trust Agent** is the in-app assistant that helps you do the connecting. They share a word and nothing else.
</Note>

## What you'll need

Whichever path you take, you type **three** values and **pick** two:

| Value | How it's entered | Where it comes from |
|---|---|---|
| **Anthropic API key** | Typed, write-only | A long-term Claude Platform on AWS key |
| **AWS Region** | Typed, e.g. `us-east-1` | Where your Claude Platform on AWS workspace runs |
| **Workspace ID** | Typed, e.g. `wrkspc_…` | The Anthropic workspace that owns the agent — find it at `platform.claude.com/settings/workspaces` |
| **Agent** | Picked from a list | Discovered for you once the three above are filled in |
| **Environment** | Picked from a list | Discovered alongside the agent |

You don't look the **Agent** and **Environment** up. Both surfaces gate them behind a **Find agents** button that reads your workspace and turns them into dropdowns of human names — the underlying identifiers are stored, never typed.

You'll also need a **Trust AI Project**. If you don't have one yet, start with [Your first 10 minutes in Trust AI](/tutorials/quickstart).

## Connect in the chat

<Steps>
  <Step title="Ask the Trust Agent">
    Open a chat in your Project and ask:

    > *"Connect my agent"* — or *"I want to connect my Claude-managed agent."*

    The Trust Agent first checks what's already connected, so it doesn't make you reconnect something that works. If nothing is connected — or you tell it you want a new one — it asks which platform your agent runs on. It never assumes.

    For a Claude-managed agent it does **not** send you to Settings. It opens a secure connection card directly in the conversation and waits.
  </Step>

  <Step title="Enter your key, region, and workspace">
    **You should see:** a card headed **Connect your Claude Managed Agent**, with a lock icon and the line *"Collecting your API key securely — it's encrypted, entered only here, and never shown or stored in this chat."*

    Fill in **Anthropic API key**, **AWS Region**, and **Workspace ID**. The key field is masked as you type.
  </Step>

  <Step title="Find your agents">
    Click **Find agents**. Until all three values are filled in the button is disabled and the card says *"Enter your API key, region, and workspace ID first, then find your agents."*

    **You should see:** two new dropdowns, **Agent** and **Environment**, listing what that key can reach by name. Pick one of each. Changing the key, region, or workspace afterwards clears the results, so you never save a pick that belonged to different credentials.
  </Step>

  <Step title="Connect">
    Click **Connect**. Trust AI saves the connection and immediately runs a real check against it — see [The check that runs on save](#the-check-that-runs-on-save).

    The Trust Agent then reports the result in plain language — **Connected to** followed by your agent's name when the check came back healthy, or *"Connection set up — the health check came back …"* naming the health outcome — *unreachable*, for example — when it didn't. The reason behind an unhealthy result is recorded on the connection itself, not written into the chat; you read it on the connection's health. No key and no secret go back into the conversation.

    **Not now** closes the card without connecting; the Trust Agent replies *"You closed the connection card. I'll wait for your next message."* A closed card leaves that line and nothing else — there is no button on it to bring it back. Ask the Trust Agent to connect again and it opens a fresh card.
  </Step>
</Steps>

### Your API key never reaches the model

This is the reason the card exists, and it is worth being precise about.

- The Trust Agent opens the card by calling a tool whose arguments carry only the platform and the project. There is no field on that call a secret could travel in.
- Your key is typed into the card and sent straight to Trust AI's backend. It is not part of the conversation, so the model that is helping you never sees it.
- What comes back to the conversation when you finish is the **outcome only** — whether the connection is live, the human names of the agent and environment you picked, and the health result. The saved connection's own id rides along as a routing key and is never rendered anywhere you can see it. No key, no secret.
- If you paste something that looks like an API key into the chat by mistake, Trust AI strips it before it is stored; the Trust Agent sees `[redacted API key]` and will ask you to use the card instead.

<Note>
  A saved key is write-only everywhere afterwards. It is never displayed back — not on the connection card, not in the edit form, not in API responses. To change it, you enter a new one.
</Note>

## Connect from Project Settings

The connection form is the manual path, and the only place to edit or delete a connection that already exists.

<Steps>
  <Step title="Open the connection form">
    In your Project, open **Project Settings**, select the **Connection** tab, and click **Add connection**.

    **You should see:** the **Add a connection** picker with **four** platform cards — **AWS Bedrock AgentCore**, **Salesforce Agentforce**, **Claude Managed Agent**, and **Conversational HTTP agent**. Choose **Claude Managed Agent**.

    The form opens under a breadcrumb reading Connections › Add › Claude Managed Agent, headed **New connection** with a **Claude Managed Agent** chip and a **Change** link beside it. There is no field to set the platform — you already chose it in the picker.
  </Step>

  <Step title="Name the connection and fill in the three values">
    Give the connection a **Connection Name** you'll recognize later — it becomes the label of the Agent Version, so "Support agent (staging)" beats "Claude 1".

    Then fill in **Anthropic API key**, **AWS Region**, and **Workspace ID**.
  </Step>

  <Step title="Find your agents">
    Click **Find agents**, then pick from the **Agent** and **Environment** dropdowns. Before discovery runs they are disabled and read *"Find agents to choose"*.

    An **Enter IDs manually** link reverts both to plain text inputs. It exists for the rare case discovery can't reach a resource; the discovery path is the one to use.
  </Step>

  <Step title="Test the connection (optional)">
    **Test Connection** runs one authenticated probe against the agent and environment as entered, and reports success or the reason it failed above the buttons.

    On a new, unsaved connection the test saves nothing. On an **existing** connection opened with **Edit**, the test is anchored to that saved connection: any secret you left blank is backed by the stored one, and the result is recorded against the connection's health.

    The test is optional — the check that actually matters runs on save.
  </Step>

  <Step title="Save the connection">
    Click **Save connection**.

    **You should see:** the connection in the **Connections** list, with a card showing **Region**, **Workspace ID**, **Agent**, **Environment**, and the **Anthropic API key** as a masked value. Where discovery resolved a human name, the card leads with that name and prints the stored identifier beneath it.

    Below those values, a **Current agent version** row names the registered [Agent Version](/concepts/agent-versions) and opens its [Agent Profile](/concepts/agent-profile) — what that build of your agent exposes.
  </Step>
</Steps>

## The check that runs on save

Saving a Claude Managed Agent connection is not a silent write. Trust AI opens one short-lived, authenticated session against the agent and environment you picked, records what happened, and shows it as the connection's health. Editing the connection re-runs it, so a corrected credential is re-checked rather than leaving a stale result.

A connection's health reads as one of **Not checked**, **Healthy**, **Degraded**, or **Unreachable**. The check on save records **Healthy** when the session opened and **Unreachable** when it didn't — and an **Unreachable** result carries the reason, for example *"Anthropic API key invalid or expired."*, so you can fix the right field instead of guessing.

A connection is saved either way. **Unreachable** means the credentials didn't work, not that nothing was stored: open the connection with **Edit**, correct the value, and save again.

## Edit or delete a connection

**Edit** reopens the form on the saved connection. The **Anthropic API key** field is blank and carries a **Configured** status pill plus the placeholder `•••• configured — leave blank to keep existing` — the stored key has no representation in the form, so it can't be shown back. Leave it blank to keep the existing key; type a new one to replace it. Because the stored key isn't available to the form, **Find agents** needs you to re-enter the key before it will search again, and says so.

The delete button does not remove the connection on the spot. It opens a confirmation dialog headed **Delete connection**, naming the connection and warning that *Trust AI will stop pulling sessions and new evaluations cannot run until a connection is re-added*, with **Cancel** and **Delete**.

## Where sessions come from

A Claude Managed Agent connection has no historical session import. The **Sync now** dropdown on the Sessions page lists every connected agent grouped by platform, but historical sync supports AWS Bedrock AgentCore only. Picking a Claude Managed Agent there returns a typed *"Sync not supported"* message naming the platform, rather than silently importing nothing.

Sessions for this connector are created when Trust AI drives the agent:

- **Explorations** the Trust Agent runs after connecting, so you can watch your agent working before anything is scored
- **Simulated conversations** — from the [Playground](/concepts/playground), or fanned out per persona when an evaluation runs [scenarios with simulation](/how-to/simulate-with-scenarios)
- **Evaluation runs** against the connected Agent Version

Each lands on the [Sessions](/concepts/sessions) surface. If you want to see which of those a session came from, turn on the **Source** column: it is hidden by default. Click **Add column** at the right edge of the Sessions table header and pick **Source** under **Hidden columns**.

Connected Agent Versions are also readable programmatically — see the [API Reference](/api-reference) for the response shape.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Find agents is disabled, or says to enter the key first">
    Discovery is gated on all three typed values — **Anthropic API key**, **AWS Region**, and **Workspace ID**. Fill in whichever is missing.

    On an **Edit** form the message is *"Re-enter your API key to search again."* That is expected: the saved key is write-only, so the form has nothing to search with until you paste one.
  </Accordion>

  <Accordion title="Find agents returns nothing">
    The card and the form both say *"No agents or environments found in this workspace."* The usual cause is the wrong **Workspace ID** — check it against `platform.claude.com/settings/workspaces` and confirm the key belongs to that same workspace.
  </Accordion>

  <Accordion title="The connection saved but reads Unreachable">
    The check that runs on save couldn't open a session with the values as stored. The result carries the reason:

    1. An invalid or expired **Anthropic API key** — the saved key is never shown back, so if in doubt, edit the connection and paste it again.
    2. An **AWS Region** that isn't where the workspace runs.
    3. An **Agent** and **Environment** that don't belong together — an agent paired with an environment it isn't published to won't resolve.

    Fix the field and save; the check re-runs on every edit that changes the connection.
  </Accordion>

  <Accordion title="The agent doesn't appear in the evaluation launcher">
    The launcher lists connected Agent Versions. Confirm the connection saved — it should be in the **Connections** list under **Project Settings → Connection** — and that you're launching from the same Project the connection belongs to. Asking the Trust Agent *"Which agent is connected now?"* is the quickest cross-check.
  </Accordion>

  <Accordion title="Sync now doesn't import my agent's past conversations">
    That's expected — historical session import isn't available for Claude Managed Agent connections, and picking one under **Sync now** says so rather than importing nothing silently. See [Where sessions come from](#where-sessions-come-from) above.
  </Accordion>
</AccordionGroup>
