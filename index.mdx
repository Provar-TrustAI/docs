Provar Trust AI is an **agent evaluation platform** for the teams building, integrating, and operating production AI agents. Connect your agent, read what it can actually do, and define scenarios — persona-and-goal test cases with an authored expected output. Simulate those scenarios against the live agent, grade the conversations they produce alongside the real ones your agent already had, record your own verdicts, and calibrate the automated judges until they agree with you — all before a change ships to customers.

A built-in **Trust Agent** drives that loop for you in plain language, from an empty project to a first scored evaluation. It stops and asks before it writes anything; grant it a standing approval for a repeated write and that one kind of write commits without asking again, with a chip in the composer showing the grant is live.

## The evaluation loop in 60 seconds

Trust AI is built around one loop: **connect → define → simulate → author → run → read → calibrate**. It closes back on itself — the last step tightens the tests the first one defined.

**Before the loop: connect and profile.** Trust AI connects to **four** agent platforms, each with its own setup: [AWS Bedrock AgentCore](/how-to/connect-agentcore), [Salesforce Agentforce](/how-to/connect-agentforce), a [Claude Managed Agent](/how-to/connect-claude-managed-agent), and the [Conversational HTTP agent](/how-to/connect-http-agent) — any agent that accepts AG-UI run requests and streams AG-UI events back. Agentforce is the one that works differently: instead of handing over a key, a secret, or a certificate, a Salesforce administrator signs in once and approves TrustAI, which then deploys its own External Client App into the org and keeps the credentials server-side. Once an agent is connected, generate an [Agent Profile](/concepts/agent-profile) — a structured, reviewable read of what a specific [Agent Version](/concepts/agent-versions) can do, its tools, routes, and knowledge sources — so you write tests against the real surface instead of guessing at it.

1. **Define** [Scenarios](/concepts/scenarios) — each one a named persona-and-goal test case with a stable id like `SCN-000123`. Author them by hand, save one from a [Playground](/concepts/playground) conversation, adopt the curated starters with **Add recommended scenarios**, or ask the Trust Agent to draft them. Every project keeps them in one flat, searchable Scenarios list.
2. **Simulate** them against your connected agent. Each persona runs one conversation, and every simulated conversation lands as a real [Session](/concepts/sessions) beside the ones synced from your runtime.
3. **Author** each scenario's **Expected Output** — the grading contract. Attach the evaluators that grade it, and set the deterministic checks: **Expected actions** and **Expected routes**, both picked from vocabulary Trust AI learned from your own sessions. Two kinds of [Evaluator](/concepts/evaluators) are yours to create, and the create form opens on a **Kind** chooser: an **LLM judge**, which grades against plain-language criteria you write, and a **Groundedness judge**, which [checks every claim against source material](/how-to/check-answers-against-source-material) and quotes the evidence. Attach a Groundedness judge and a **Reference material** section appears on the same tab, holding the documents that scenario's answers must be grounded in.
4. **Run** an [Evaluation](/concepts/evaluations) from one launcher, scoped to a specific Agent Version — against scenarios, which simulate fresh conversations, or against sessions that already happened, which are graded as recorded. Repeat each test case up to four times for a reliability read.
5. **Read** the results, grouped **by scenario**. The headline leads with **Pass rate** — how often the agent passed. **Evaluator accuracy** — how often the judges' combined verdict matched a human's — joins it as a second headline, but only once human verdicts exist to grade the judges against. Each leg stands down when it has nothing to report: a run with no behavioral grading reads **Not graded**, and the accuracy headline is simply absent rather than showing a zero.
6. **Record** human [verdicts](/concepts/annotations) on the conversations — pass or fail, severity, notes. This is the ground truth the automated judges are measured against, and it is never a prerequisite for running an evaluation.
7. **Calibrate** each judge against those verdicts until it agrees with your reviewers, then tighten the scenarios and run again.

Read the full narrative at [The evaluation loop](/concepts/evaluation-loop). Starting from an empty project? Ask the Trust Agent — it takes you from connecting your agent, through an observe-only look at its behavior, to your first scored evaluation, all in one conversation. Work through the capstone tutorial: [Evaluate with the Trust Agent](/tutorials/evaluate-with-the-trust-agent).
