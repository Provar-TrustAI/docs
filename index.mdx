Provar Trust AI is an **agent evaluation platform** for the teams building, integrating, and operating production AI agents. Connect your agent and TrustAI starts reading what it can actually do. Write down what that agent must do and must never do as [Requirements](/concepts/requirements), turn each requirement into scenarios — persona-and-goal test cases with an authored expected output — and simulate them against the live agent. Grade the conversations they produce alongside the real ones your agent already had, record your own verdicts, and calibrate the automated judges until they agree with you — all before a change ships to customers.

A built-in **Trust Agent** drives that loop for you in plain language, from an empty project to a first scored evaluation. It stops and asks before it writes anything; grant it a standing approval for a repeated write and that one kind of write commits without asking again, with a chip in the composer showing the grant is live. Each turn runs on a model you pick from the ones your workspace offers, at a thinking depth you set per message, and **Stop** ends a reply you no longer want.

## The evaluation loop in 60 seconds

TrustAI is built around one loop: **specify → define → simulate → author → run → read → record → calibrate**. It closes back on itself — the last step tightens the tests the first one defined.

**Before the loop: connect and profile.** TrustAI connects to **four** agent platforms, each with its own setup: [AWS Bedrock AgentCore](/how-to/connect-agentcore), [Salesforce Agentforce](/how-to/connect-agentforce), a [Claude Managed Agent](/how-to/connect-claude-managed-agent), and the [Conversational HTTP agent](/how-to/connect-http-agent) — any agent that accepts AG-UI run requests and streams AG-UI events back. Agentforce is the one that works differently: instead of handing over a key, a secret, or a certificate, a Salesforce administrator signs in once and approves TrustAI, which then deploys its own External Client App into the org and keeps the credentials server-side. Connecting an agent also starts its [Agent Profile](/concepts/agent-profile) for you — a structured, reviewable read of what a specific [Agent Version](/concepts/agent-versions) can do, its tools, routes, and knowledge sources. You do not have to go and ask for it: a freshly connected agent lands on **Profile queued** or **Profile in progress**. **Generate profile** is the fallback for an agent whose capture never ran, and **Try capturing again** for one whose capture failed. All of it is listed, checked, and customized on one surface: the **Connections** tab in [project settings](/how-to/manage-project-connections).

1. **Specify** what the agent must do and must never do as [Requirements](/concepts/requirements), in the language your business already uses. This is the step everything downstream hangs off, and the Trust Agent enforces the order: ask it for scenarios before a requirement is saved and it refuses, offering to draft the requirements with you first.
2. **Define** [Scenarios](/concepts/scenarios) against those requirements — each one a named persona-and-goal test case with a stable id like `SCN-000123`. Author them by hand, save one from a [Playground](/concepts/playground) conversation, adopt the [recommended security scenarios](/concepts/trust-library), or ask the Trust Agent to draft them. Every project keeps them in one flat, searchable Scenarios list.
3. **Simulate** them against your connected agent. Each persona runs one conversation, and every simulated conversation lands as a real [Session](/concepts/sessions) beside the ones synced from your runtime. A scenario can carry pictures too, and the simulated customer decides for itself which one helps and when.
4. **Author** each scenario's **Expected Output** — the grading contract. Attach the evaluators that grade it, and set the deterministic checks: **Expected actions** and **Expected routes**, both picked from vocabulary TrustAI learned from your own sessions. Two kinds of [Evaluator](/concepts/evaluators) are yours to create, and the create form opens on a **Kind** chooser: an **LLM judge**, which grades against plain-language criteria you write, and a **Groundedness judge**, which [checks every claim against source material](/how-to/check-answers-against-source-material) and quotes the evidence. Attach a Groundedness judge and a **Reference material** section appears on the same tab, holding the documents that scenario's answers must be grounded in. A scenario that needs records to exist before the conversation starts gets a [test data](/concepts/test-data) plan on its own tab — what the run creates, reads back, checks, and cleans up afterwards.
5. **Run** an [Evaluation](/concepts/evaluations) from one launcher, scoped to a specific Agent Version — against scenarios, which simulate fresh conversations, or against sessions that already happened, which are replayed to your connected agent so the answer it gives *now* is what gets graded. Repeat each test case up to four times for a reliability read. To grade a single conversation instead, open it from **Sessions** and click **Evaluate**: that quick evaluation scores it in place and lands on the Evaluations list carrying a muted **Quick** pill.
6. **Read** the results, grouped **by scenario**. The headline leads with **Pass rate** — how often the agent passed. **Evaluator accuracy** — how often the judges' combined verdict matched a human's — joins it as a second headline, but only once human verdicts exist to grade the judges against. Each leg stands down when it has nothing to report: a run with no behavioral grading reads **Not graded**, and the accuracy headline is simply absent rather than showing a zero. A conversation whose own agent action returned an error reads the amber **Couldn't test** and leaves the denominator, so a green pass rate never quietly hides a conversation nothing could grade.
7. **Record** human [verdicts](/concepts/annotations) on the conversations — pass or fail, severity, notes. This is the ground truth the automated judges are measured against, and it is never a prerequisite for running an evaluation.
8. **Calibrate** each judge against those verdicts until it agrees with your reviewers, then tighten the scenarios and run again.

Read the full narrative at [The evaluation loop](/concepts/evaluation-loop). Starting from an empty project? Ask the Trust Agent — it takes you from connecting your agent, through an observe-only look at its behavior, to your first scored evaluation, all in one conversation. Work through the capstone tutorial: [Evaluate with the Trust Agent](/tutorials/evaluate-with-the-trust-agent).

The product and the Trust Agent are not the only two ways to drive this loop. TrustAI is also an **MCP server**: an agent in your own client connects with a URL and one browser consent screen, then writes requirements, scenarios and judges, launches runs, and adjudicates results without opening the product. See [MCP integration](/concepts/mcp-integration).

Administering the workspace? Manage members, teams, and per-project Viewer, Editor, and Admin access from **Workspace settings** — no code required. See [Administer workspace access](/how-to/administer-workspace-access).
